# Role Play Feedback Email Backend Spec

## Context

Frontend page:

`https://www.justproveit.co.uk/admin/role-play-feedback`

The page is CRM-authenticated and lets a reviewer complete six pension role play scenarios. At the end, the frontend sends the completed feedback to the evaluated agent by email.

## Endpoint

Add:

`POST /api/justproveit/admin/role-play-feedback/email`

Auth:

`Authorization: Bearer <CRM token>`

Only CRM/admin users should be allowed to send this email.

Content type:

`application/json`

## Request Payload

The frontend sends:

```json
{
  "tenantKey": "justproveit",
  "source": "pension-role-play-feedback",
  "agentName": "Agent Name",
  "agentEmail": "agent@example.com",
  "reviewerName": "Reviewer Name",
  "reviewerEmail": "reviewer@example.com",
  "sessionDate": "2026-08-19",
  "summary": {
    "totalItems": 22,
    "completedItems": 22,
    "missingItems": 0,
    "yes": 15,
    "partial": 4,
    "no": 2,
    "notApplicable": 1,
    "scorePercent": 81
  },
  "summaryText": "Plain-text ready-to-send summary generated by the frontend.",
  "strengths": "What went well.",
  "improvements": "What should improve.",
  "overallNotes": "General notes.",
  "domain": "www.justproveit.co.uk",
  "pageUrl": "https://www.justproveit.co.uk/admin/role-play-feedback",
  "referrer": "",
  "scenarios": [
    {
      "id": "scenario-1",
      "title": "Scenariul 1 - Calificare, legitimitate si pret",
      "participantRole": "agent",
      "feedbackItems": [
        {
          "id": "registration-number",
          "label": "A mentionat numarul de inregistrare UK (14007642)?",
          "status": "yes"
        }
      ],
      "notes": "Optional scenario notes."
    }
  ]
}
```

Allowed `participantRole` values:

- `agent`
- `client`
- `observer`

Allowed feedback item `status` values:

- `yes`
- `partial`
- `no`
- `na`

## Required Email Behavior

Send one email to `agentEmail`.

Recommended subject:

`Feedback role play pensii - {sessionDate}`

Recommended sender:

Use the existing JustProveIt/CRM Resend sender configuration.

Recommended reply-to:

Use `reviewerEmail` if present and valid.

Email body:

- Greeting with the agent name.
- Include the summary score and counts.
- Include all six scenario sections with every feedback point and status.
- Include scenario notes.
- Include final sections: strengths, improvements, overall notes.
- The frontend already provides `summaryText`; backend can use it directly for the plain-text body, or render a nicer HTML email from the structured `scenarios` array.

## Response

Success must only be returned if Resend accepts the send:

```json
{
  "success": true,
  "emailSent": true,
  "message": "Feedback email sent.",
  "result": "resend-message-id"
}
```

Failure examples:

```json
{
  "success": false,
  "emailSent": false,
  "message": "Invalid agent email."
}
```

or return a non-2xx response with a useful `message` or `error.message`.

Important: do not return `success: true` unless a provider message id exists or Resend has accepted the email.

## Validation

Backend should validate:

- `tenantKey` is `justproveit`
- authenticated user has CRM/admin access
- `agentEmail` is a valid email
- `agentName`, `reviewerName`, `sessionDate`, `summary`, and `scenarios` are present
- `scenarios` has the expected six scenario ids
- all feedback items have allowed statuses

## Logging

Safe logs may include:

- scenario count
- reviewer user id/name
- agent email domain only
- Resend message id
- success/failure code

Do not log full email addresses or the full feedback body unless existing compliance rules allow it.

## Acceptance Criteria

- A CRM-authenticated user can submit the completed feedback from `/admin/role-play-feedback`.
- The evaluated agent receives one email with all six scenarios and the final debrief.
- The frontend receives `success: true` and `emailSent: true` only after Resend accepts the email.
- If Resend/template/email validation fails, the frontend receives a clear failure response and shows the error.
